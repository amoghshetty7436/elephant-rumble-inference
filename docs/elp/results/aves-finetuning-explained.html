Tuning AVES for elephant rumbles

What AVES looks like inside, which parts we could retrain, what LoRA is, and the order I'd try things in.

The model today

Every 0.64 seconds of audio (320 samples at 500 Hz) becomes one fingerprint: 768 numbers from AVES. AVES learned to hear from a large collection of animal sounds, but it has never been told what a rumble is. Today it is frozen: we never change its 94.4 million weights. We only train our small classifier on top, which turns fingerprints into "rumble or not".

Why retrain only the top

The lower layers learn things every sound has: onsets, pitch, harmonics, noise texture. These are just as useful for rumbles, and retraining them with our ~250 training days would mostly risk breaking them. The top layers combine those into higher-level "what is this sound" features, so that is where teaching AVES about rumbles pays off.

There's a practical reason too. If layers 1 to 8 stay frozen, we can run them once over all training audio and cache layer 8's output, the same way we cache fingerprints now. Training then only has to run layers 9 to 12 and the classifier, which is about a third of AVES and much faster than running the whole model at every step.

There's no "B": B would be fine-tuning all of AVES, which I'd skip. It's slow, it needs far more data than we have, and it risks damaging what AVES already knows.

What LoRA is

Inside each transformer layer, the main work is done by big tables of weights. One of them is 768 × 768, about 590,000 numbers. Fine-tuning changes all of them. LoRA (low-rank adaptation) assumes the change we need is simple, so it describes the change with two thin tables instead: one 768 × 8 and one 8 × 768. Multiplied together they make a full 768 × 768 correction that gets added to the original.

The plan after Tuesday

  1. Probe the layers. Cache layers 6 to 12 for the training and validation days, then score each layer with the same validation days, scoring and 5 seeds as the rerun.
  2. Fine-tune the top 2 layers, then the top 4, starting from the rerun's best training recipe (its data mix, window size and alarm rule). The learning rate for AVES is about 100 times smaller than for the classifier, with the same early stopping on held-out days.
  3. LoRA, rank 4 and 8, on the top 4 layers. Keep whichever of C or D wins on the score, with fewer weights changed as the tie-breaker.
  4. Check the winner on the test sets (Test 1, Test 2, vehicle days) once, exactly as the rerun does. Then re-run the CPU speed test to confirm nothing got slower.

Like everything else, this will be a separate new script that doesn't touch your existing code, and it writes only under Configurations. It can't run at the same time as the rerun, because both need the GPU.
